# Asylum IBW AFM Implementation Plan

> **For agentic workers:** Use superpowers:subagent-driven-development. Follow the project PRD and per-item verification loop.

**Goal:** Preserve IBW data and deliver reproducible AFM processing and measurements in Image Analysis.

**Architecture:** Keep the offline, injected single-HTML architecture. Preserve source data separately from derived displays and computations, and retain calibrated physical coordinates and provenance. Add focused tests against independent numerical values before implementation.

**Tech Stack:** Existing JavaScript, Python injection and Playwright; no new runtime or package manager.

**Spec:** docs/PRD.md

## Global Constraints
- Preserve existing behavior and project conventions; never claim that altered values are identical to source values.
- Do not alter unrelated modules; do not deploy. No Git repository exists here; use a reversible working copy and preserve originals.
- Verify each WBS item before the next, log findings and skipped tests in docs/PROGRESS.md.
- Binary raw data, display rendering, processing outputs, and exports have distinct precision and calibration requirements.

## Review Focus
1. 64-bit floats and uint32 values that collapse under Float32 rounding; check exact original numeric values.
2. Unknown channel units and endian variants; never invent units and compare supported decoded values.
3. Rectangular pixels and reversed or missing calibration; compare horizontal, vertical, and diagonal paths.
4. NaN, masks, tiny ROIs and singular fit surfaces; compare explicitly defined behavior.
5. Modified data, original file, reopening and multiple channels; check provenance and lossless export claims separately.
