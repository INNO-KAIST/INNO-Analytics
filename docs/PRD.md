# PRD: Asylum Research IBW AFM 이미지 분석

* 작성일: 2026-11-05
* 승인 상태: [ ] 대기 / [x] 승인됨 (2026-11-05)

## 1. 목표
Image Analysis에서 Igor Pro 6/Asylum Research의 IBW AFM 이미지 채널을 신뢰성 있게 열고, 원본을 보존하면서 후처리·정량 분석·결과 저장을 수행한다.

## 2. 범위 (In)
- 기존 단일 HTML·브라우저 오프라인 구조와 modules/image 원본 및 주입 절차 유지.
- 실측과 합성 파일을 바탕으로 지원 IBW 변형, 채널, 자료형, 메타데이터, 방향 및 물리 보정 확인. 지원하지 못하는 경우 명시적인 오류 또는 경고.
- 원본 화소 격자와 원본 수치 정밀도 보존; 표시용 축소와 분석 데이터 분리. 편집은 계산된 새 결과로 관리하고 원본 및 이력 보존.
- 대표 AFM 이미지 후처리: 평면 기울기 및 행별 보정, 배경/다항식 보정, 필터와 마스크·ROI, 처리 매개변수와 이력.
- 정량 분석: 보정된 선 단면·높이/단차, ROI 통계 및 표면 거칠기(Sa/Sq 등 정의 명시), 높이 분포, 입자/영역 측정. 단위와 마스크·결측치 규칙 명시.
- 데이터 정밀도를 보존하는 수치 내보내기와 표시 이미지 내보내기 구분, 보정·단위·처리 이력 전달 여부를 명시.
- 기존 기능 회귀, 합성 기준값, 독립 도구 및 제공 가능한 실측 Asylum 파일 대조; 가이드와 기존 SPEC 갱신.

## 3. 비범위 (Out)
- 모든 AFM 장비·IBW 변형에 대한 무조건적 호환 보장. 실측 검증 범위 밖은 명시한다.
- Force curve/force volume, 실시간 장비 제어 및 별도 서버 운영. 이미지 이외 데이터가 발견되면 명확히 안내한다.
- 원본 데이터의 물리적 정보까지 복원하는 처리 또는 편집 중 보간·필터로 바뀌는 값을 무손실이라 주장하는 것.

## 6. 위험 및 가정
- 현 코드의 IBW 리더 및 분석 엔진은 Float32Array 중심이므로 float64 및 큰 정수 입력의 정밀도 손실 가능성이 확인됐다. 분석 연산과 저장 경로까지 검증해야 한다.
- 사용자 제공 실측 파일과 장비의 기준 결과가 없으면 해당 조합의 완전 호환을 입증할 수 없다. 현재 시험은 실측 IBW 데이터가 없으면 자동으로 건너뛴다.
- 모든 후처리와 모든 AFM 분석을 열거 없이 완성했다고 보장할 수 없다. 위 범위를 1차 완료 범위로 제안하며 구체 작업 목록 및 허용오차는 승인 후 기준 사례 조사로 명시한다.
- 새 언어/빌드 도구/런타임 추가 여부: 현재로서는 추가하지 않음. 필요성이 발견되면 변경 요청으로 별도 승인받는다.
- E: 프로젝트 폴더는 현재 샌드박스 쓰기 허용 범위 밖이므로 문서 및 구현 변경 시 실행 환경의 별도 쓰기 권한이 필요하다.

### 10.1 목표와 범위
Image Analysis의 AFM 영상에서 각 주사선을 개별적으로 보정하고, 입자·구조물이 기저 피팅을 왜곡하지 않도록 제외하며, 적용 전에 원본과 결과를 같은 조건으로 비교한다. 기존 오프라인 단일 HTML, 모듈 주입, 일반 이미지 기능, 원본 IBW 및 물리 단위를 유지한다.

### 10.4 위험과 가정

- 각 scan line의 피팅은 실제 표면의 넓은 입자·단차·곡률도 제거할 수 있다. 마스크는 피팅 제외 의미를 명확히 표시하고 기본 비파괴 미리보기와 원본 보존을 제공한다. 보정 후 Sa/Sq가 달라질 수 있으며 자동으로 물리적 진실을 보장하지 않는다.
- 새 언어/빌드 도구/런타임 추가 여부: 제품에는 추가하지 않는다. 기존 테스트용 Node·Python·Chromium·Gwyddion/NumPy를 사용하고 별도 도구가 필요하면 먼저 기록·승인받는다.
- 사용자가 이전에 허가한 세 실측 폴더는 읽기 전용으로만 사용한다. Gwyddion의 내장 API가 현재 Windows 환경에서 실행되지 않으면 NumPy 독립 대조는 수행하되 Gwyddion 직접 검증의 미수행을 명시한다.
- 행별 또는 자동 threshold 마스크의 검증은 선택된 표본과 정의에 한한다. 모든 AFM 영상, 모든 입자 또는 다른 장비의 모든 변형에 대한 완전 호환을 주장하지 않는다.
- Git이 없는 작업 폴더이므로 기존 파일 백업·격리 작업본·변경 검토를 통해 사용자 자료를 보호한다. E: 경로 쓰기는 실행 환경의 별도 권한이 필요하다.

### 10.6 독립 검토에 따른 상세 기준

- 마스크 값이 **유한하고 0이 아니면 피팅에서 제외**, 0이면 포함한다. 기존 core의 1=포함 fitMask에 전달할 때 극성을 명시적으로 변환하며, NaN/Inf 마스크는 거부한다. 크기와 선택된 채널·Z·시간 평면 및 좌표 정렬을 확인한다. 마스크를 제외하는 것은 피팅 표본에만 적용하고, 보정은 마스크 아래 입자를 포함한 지정 적용 영역에 수행한다.
- 피팅점 부족·특이성 검사는 실제로 유한한 적용 화소가 있는 scan line에 적용한다. 적용 영역에 유한 화소가 전혀 없으면 오류다. 부족한 행을 건너뛰거나 차수를 낮추지 않는다. 0차와 기존 Row mean의 동등성은 동일 방향·피팅/적용 범위에서 검증한다.
- 마스크를 참조하는 이력/매크로에는 마스크 내용의 안정적인 식별(강한 해시 또는 스냅샷)과 차원·평면·극성을 기록한다. 삭제·내용 변경·재시작·다른 이미지 batch 재생 시 원래 마스크를 확인할 수 없거나 정렬이 맞지 않으면 조용히 다른 마스크를 적용하지 않고 명확히 오류를 낸다.
- 측정 결과·원본·마스크는 미리보기 계산 중 바뀌지 않는다. 결과 모드가 새 이미지인 8/16-bit 다중 평면 스택에서는 원래 스택이 유지되고 새 결과에서 Undo를 검증한다. 미리보기 취소·다른 이미지/평면 전환·지연된 worker 반환·한도 초과는 원본을 변형하지 않는다.
- 독립 수치 대조는 위치별 finite 여부와 NaN/±Inf 보존을 별도로 검사한다. 유한 실측 화소는 출발 기준 `|앱−참조| ≤ 1e-8 nm + 1e-10×max(|참조|)`로 검사하고, 0차 동등성·합성 값·큰 offset/단위별 허용오차는 시험마다 적합성을 명시한다. 조건이 충족되지 않는 실측 행이나 도구는 무리하게 통과시키지 않고 미검증 범위로 기록한다.
- 기존 Preview는 AFM의 이미지 연산에서 바로 사용되지 않으므로, 계산과 확정 경로를 분리하고 오래된 비동기 응답을 무효화하는 전후 비교 인터페이스를 별도로 검증한다. 큰 영상은 기존 메모리 제한을 적용하고 축소된 미리보기를 수치 데이터로 사용하지 않는다.

- 기존 오프라인 단일 HTML과 JS/Node·Python·Chromium 테스트 스택을 사용한다. **새 언어·제품 런타임·빌드 도구 추가 없음**을 가정한다.
- 이미지의 화면 좌표계는 실제 장비의 절대 좌표나 원점과 다를 수 있다. CSV와 메타데이터에 기준을 명시하고, 무보정 정보는 추정하지 않는다.
- 기존에 승인된 AFM 실측 폴더는 읽기 전용으로 사용하고 자료의 외부 전송·공개 커밋을 금지한다. RGB PNG의 표시 색에서 실제 물리량을 복원하지 않는다.

### 독립 검토에 따른 상세 기준
- 원본 IBW 샘플의 격자·방향·원본 축척과 SI 단위를 확인할 수 없는 경우, 또는 crop·flip·rotate·보정값 변경 등으로 원본과 현재 영상의 대응을 검증할 수 없을 경우 원본 선택을 차단한다. 현재 영상의 메타데이터를 원본에 임의로 붙이지 않는다.
- CSV와 필수 JSON은 단일 평면을 포함해 모두 ZIP 하나에 넣는다. 파일명 정규화·중복·경로 탈출·ZIP 크기 및 메모리 상한을 검사한다. 미지원 이미지가 섞인 경우 조용히 누락하지 않고 목록과 함께 중단한다.
- 비동기 내보내기 중 데이터·평면·보정·메타데이터가 바뀌면 일관된 스냅샷을 쓰거나 결과를 만들기 전에 명시적으로 중단한다.
- NaN은 의미를 보존하며 payload 비트의 동일성은 보장하지 않는다. Excel은 숫자를 약 15자리로 반올림할 수 있으므로 정확한 재읽기는 Float64를 지원하는 도구에서 수행하도록 안내한다.


### 12.1 색상·측정값 출처 추적 확장 (2026-11-06 사용자 승인)
- 사용자는 제시된 2번(전체 이미지 형식의 색상/수치 출처 추적 확장)을 선택하여 중단된 CSV 작업 재개를 승인했다. 파일 입력·복제·채널 분리·명시적 회색 변환·기하 처리·Undo·세션 및 numeric snapshot 저장/재열기에서 확인된 수치, 색상 또는 색 성분, 명시적 회색 변환, 출처 불명을 일관되게 구분한다.
- 구버전 snapshot·세션의 미기록 출처는 채널 수와 관계없이 임의 추정하지 않으며, CSV 적용 가능 여부와 이용자 안내 정책을 명시하고 시험한다. 실제 AFM 수치 채널은 과도하게 차단하지 않는다. 변환된 회색의 값은 시각 명암이지 물리 측정값 복원이 아님을 표시한다.
- 각각의 경계는 실패 재현 시험, 독립 검토, 전체 기존 회귀 및 실측 AFM 수치·단위 시험을 통과해야 한다. 새 런타임/빌드 도구 없이 기존 오프라인 구조 유지. Bruker·Park PRD §11 및 후처리·파일명 요청은 별도 상태로 유지한다.

## 13. 내보내기 파일명: 원본파일명_채널명 (2026-11-07 승인)

- 사용자 승인: 2026-11-07. PNG와 CSV의 이름을 원본파일명_채널명으로 지정하고 중복 채널·평면을 구분한다. 기존 CSV 수치·출처 검증 및 이미지 데이터 불변을 유지한다.
- NM-01: PNG 출력은 실제 원본 파일 확장자를 제거하고 실제 채널명을 사용한다. 예: SKPM_AAA.ibw의 Height Retrace → SKPM_AAA_Height Retrace.png. 채널명이 없거나 출처 미확인 시 명시적으로 안전한 대체 이름을 사용하며 임의로 채널을 추정하지 않는다.
- NM-02: ZIP 내 각 CSV는 동일한 원본·채널 기본명, 필요한 경우 C/Z/T 및 중복 순번을 덧붙여 식별한다. 서로 다른 채널명·평면·같은 이름의 열린 이미지 및 동일 채널명은 대소문자 무시 충돌 없이 구분하고 JSON metadata의 파일명 참조와 실제 ZIP 이름을 일치시킨다. PNG는 현재 열린 이미지·선택 평면의 알려진 충돌을 구분한다. 기존 다운로드 폴더 파일은 브라우저가 처리한다.
- NM-03: 경로 구분자, Windows 예약명·제어문자·후행 점/공백·긴 이름·유니코드 등을 안전하게 처리하되 원본 이름과 실제 채널 라벨은 가능한 한 그대로 유지한다. 원본 데이터·단위·픽셀 배열·캘리브레이션·이력은 수정하지 않는다.
- NM-04: 합성 및 실제 IBW의 단일/여러 채널, 재열기·복제, 중복 채널·C/Z/T·한글/마침표/예약명·확장자 누락, ZIP CRC 및 metadata 대응, PNG 다운로드 파일명을 독립 브라우저/파일 시험으로 확인한다. 기존 CSV/AFM/IBW/일반 이미지 회귀와 단일 HTML 주입 멱등성 확인 후 사용자 승인에 따라 INNO-KAIST/INNO-Analytics main 및 source를 푸시·Pages 실배포를 확인한다.
