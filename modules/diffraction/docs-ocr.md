# Diffraction 탭 — 스케일바 이름표 OCR (`src/diff_ocr.js`)

스케일바 옆 글자("5 1/nm", "500 nm", "0.5 1/Å", "2 nm⁻¹" …)를 읽어 값·단위를 미리 채운다. 의존성 없음, DOM 없음 — Web Worker·Node 모두 `DIFF_OCR` 전역(+ `module.exports`).
값은 **제안**이다: UI 는 값을 채우되 편집 가능하게 두고, `conf < 0.9` 이면 확인을 묻는다.

## 1. API

```js
const r = DIFF_OCR.readScaleLabel(img, w, h, bar, opt)
// img: Float32Array 회색 (8-bit RGB 는 Rec.601 휘도), bar: {x0,x1,y0,y1} (DIFF_PATTERN.scaleBar 결과 그대로 가능)
// → { text:"5 1/nm", value:5, unit:"1/nm"|"nm"|"µm"|"Å"|"1/Å"|"pm",
//     valueInvNm: 5      // 역수 단위면 1/nm 로 바꾼 값 (1/Å → ×10), 아니면 null
//     recip: true, conf: 0..1,
//     chars: [{ch,x0,y0,x1,y1,score}], box:{x0,y0,x1,y1}, H: 글자 높이(px) }
//   또는 null (막대 없음·글자 없음·읽을 만한 것 없음 — 예외는 던지지 않는다)
// opt: { expect:"recip"|"real" (SAED 모드면 "recip" — 반대 단위에 작은 벌점), padX:420, padY:150, debug:true }

const r2 = DIFF_OCR.readAuto(img, w, h, DIFF_PATTERN.scaleBar(ov, w, h), opt)
// 힌트 막대로 읽어 conf ≥ 0.5 면 그대로, 아니면 findBars 후보(최대 5)로 다시 읽어 가장 나은 것. r2.bar = 쓴 막대
DIFF_OCR.findBars(img, w, h, {max}) / findBar(...)
// 밝은·어두운(흰 상자 안 검은 막대, 반전 영상)·속 빈(REDI)·흐린(JPEG) 막대, 글자·얼룩이 붙어 있어도 막대 행만 떼어 냄
```

단위 문법: `1/nm` · `nm-1` · `nm⁻¹` → **1/nm**, `nm`, `µm`·`um` → **µm**, `Å`·`A` · `1/Å` · `Å-1` · `Å⁻¹` → **1/Å**(valueInvNm = ×10), `pm`.
수: 숫자 + 소수점 하나, 0 으로 시작하면 `0.x` 만. 값 > 0.

## 2. 처리 순서
1. **영역**: 막대 둘레(위·아래 150 px, 좌우 420 px)만 → 2048² 영상도 막대 근처만 본다.
2. **이진화(양 극성)**: 잉크 = 막대 상자 값(밝으면 95 %, 어두우면 5 % 백분위), 바탕 = 막대 둘레 중앙값. 32 px 칸별 백분위로 국소 바탕(빔 번짐 위 글자), s = (값 − 바탕)/(잉크 − 바탕). 흰 상자 안 검은 글자, 반전 영상 모두 같은 식.
3. **성분**: 문턱 s ≥ 0.5, 0.35, 0.65 세 번 (가는 획이 끊기거나 이웃 글자가 붙는 경우). 첫 문턱에서 conf ≥ 0.97 이면 멈춤.
4. **글자 후보**: 위에 얹힌 작은 성분 합치기(Å 고리) → 줄 묶기(세로 겹침, 가로 틈 ≤ 키) → 넓은 성분 쪼개기(세로 잉크 최소 자리 2 곳, 한 번 더), 1 px 틈 조각 2·3 개 합치기, 띠보다 큰 성분(얼룩이 붙음)은 띠 안만 자른 후보.
5. **줄 높이 H·기준선**: 1 차 분류에서 숫자로 보이는 성분 무리 — 애매하면(위첨자 ¹, 상자 가장자리) 두 무리 모두 풀어 본다.
6. **분류**: 글자를 12×18 로 면적 평균(잉크 0..1) → 틀과 Σ|q − t| − Σmin(q,1−q) (흐림 바닥값을 빼서 흐린·작은 글자도 같은 잣대) + 0.25·|Δln 가로세로비| + 0.06·|Δ구멍 수| + 0.35·(|Δ높이/H| + |Δ바닥/H|). 클래스별 최소.
7. **문법 해석**: 단위마다 동적 계획 (성분 위치 × 상태: 앞 버림 → 수 → 단위 → 뒤 버림). 버리는 값: 띠 안 글자 크기 0.4 (붙어 있으면 0.75), 기준선 위 점 크기 0.3, 띠 밖 작은 얼룩 0.06.
8. **고르기**: 총비용 = 글자 비용 + 버림 + 막대에서 먼 거리(1.5 H 넘으면 0.08/H) + 값 사전(1·2·5×10ⁿ = 0, 2.5 = 0.1, 3·4·1.5·7.5 = 0.15, 그 밖 0.35; "20.0" 꼴 0.35) + 단위 사전(pm 0.15 등). 가장 낮은 문턱의 성분 중 해석에 안 쓰인 글자 크기 잉크가 옆에 있으면 벌점(문턱 사이 공정 비교).
9. **conf** = σ(6.901 + 10.801·min(여유,0.3) − 32.913·평균비용 − 20.721·사전벌점 − 15.574·문법억지/글자), 여유 = 다른 (값, 단위) 해석과의 총비용 차·자리별 차선 숫자와의 차 중 작은 것. 이름표 바로 옆 글자 크기 잉크를 버렸거나, 위첨자 자리·앞 숫자 자리에 성분이 못 된 잉크가 남으면 conf ≤ 0.6.
   계수는 **dev 묶음**(seed 7·11·23, 2450 장, 시험과 다른 미사용 글꼴 IPAPGothic·DejaVu Sans Condensed·Liberation Sans Bold) 로지스틱 맞춤 — 시험 묶음은 맞춤에 쓰지 않았다.

## 3. 글자 틀 (`ref/gen_ocr_templates.py`)
- 글꼴: Liberation Sans(Arial 치수 호환)·DejaVu Sans·FreeSans(Helvetica 계열), 각 보통·굵게. 크기 12 15 19 24 30 40 52 px, 부드러움(앤티에일리어싱) 켜고/끄고.
- 글자: `0-9 . / n m µ u A Å - p` + 위첨자 `⁻ ¹`(작은 '-'·'1' 을 0.62 배, 0.36 em 올려 그림 + 글꼴 자체 ¹) + **거절용** 대문자·소문자·`:()=,+%°'` (다른 덧글씨 "SAD 1"·"200 kV" 를 숫자로 억지로 읽지 않게 — 문법이 억지로 바꾼 정도가 conf 를 낮춘다).
- 특징 = 12×18 비트(면적 평균 후 0.5 이진화) + ln(가로/세로) + 높이/H + 바닥/H + 구멍 수, 같은 클래스 안 비트 차 ≤ 14·비율 차 < 0.12·위치 차 < 0.08 이면 하나만 → **2 509 개**, 1 개 32 B, base64 107 KB 를 `diff_ocr.js` 의 `/*TPL-BEGIN*/…/*TPL-END*/` 에 넣는다 (파일 전체 144 KB).
- 다시 만들기: `python3 ref/gen_ocr_templates.py` (약 50 s, 결정적).

## 5. 한계
- 막대 극성 첫 읽기의 틀은 고딕(sans) 3 가족뿐. 명조·고정폭 틀은 반대 극성(GMS 꼴) 읽기에서만 쓴다(§6). 이탤릭·손글씨·세로 글자·여러 줄 이름표는 대상 아님. IPA 고딕처럼 µ 가 p 에 가까운 글꼴은 µm ↔ pm·nm 을 헷갈린다(conf 는 낮게 나옴).
- 대문자 높이 10 px 아래, 흐림 + 아주 작은 위첨자(nm⁻¹ 의 ⁻¹ 이 4–5 px)는 nm 로 읽힐 수 있다 — 옆 잉크 검사로 conf ≤ 0.6 이 되게 했지만 완전히 막지는 못한다(SAED 에서는 `opt.expect:"recip"` 권장).
- 스폿이 숫자에 붙으면 다른 숫자로 높은 conf 를 낼 수 있다(시험 오답 1 건).
- 값 사전(1·2·5×10ⁿ)이 맞는 읽기를 덮지 않는지는 `odd` 60 장(98.3 %)으로만 확인했다.
- 단위는 nm·µm·Å·pm 과 그 역수(1/nm·1/Å)만. mm·mrad·1/µm·1/pm 은 없다.
- 이름표가 막대 안에 있거나 막대에서 150 px(위·아래)/420 px(좌우)보다 먼 경우는 못 찾는다(`opt.padX/padY`).
- 시험 PNG 는 14.5 MB — `python3 ref/gen_ocr_test.py` 로 같은 그림을 다시 만들 수 있다(seed 1).


## 6. GMS 기본 이름표 (2026-10-17, REDI 예제 B3·T13)
GMS 가 tif 로 내보낸 회절도의 스케일바: **흰 속 빈 막대(속은 검정) + 검은 명조 글자(Times 꼴) + 흰 그림자(글자를 3–4 px 밀어 흰색)**. 글자 몸통 = 0, 바탕 중앙값 10–13·MAD ≈ 4 → 막대와 글자 극성이 반대이고 글자 대비가 잡음 수준. 이전 판은 두 예제 모두 null.

- **순서**: ① 막대 극성 + 기본(고딕) 틀 — 이전과 같은 동작. conf ≥ 0.5 면 끝(0.6 은 '옆 잉크 남음' 으로 일부러 낮춘 확인 요청이므로 덮어쓰지 않는다).
  ② 아니면 반대 극성으로 (5×5 중앙값) → (3×3 중앙값) → (3×3 + 검은 글자 ∪ 흰 그림자) 차례로, conf ≥ 0.97 이면 멈춤. 반대 극성 결과는 **conf ≥ 0.6 일 때만** 받는다(글자 없는 잡음 영상에서 그럴듯한 엉터리 값 "1 Å⁻¹ 0.57" 이 나온 것을 독립 검토가 찾음). 막대 극성 판단이 안 되면(막대 대비 약함) 두 극성 모두. 시간 상한 1.5 s(이름표)·2.5 s(막대 여러 개).
  잉크 기준은 영역의 0.3 %·99.7 % 백분위(한 점짜리 hot pixel·포화 회절점에 끌리지 않게).
  반대 극성에서만: 기본 틀 + **추가 틀 3 534 개**(Liberation Serif 보통·굵게·DejaVu Serif·FreeSerif·Liberation Mono·DejaVu Sans Mono·FreeMono; `TPL_B64_X`), 문턱 0.65·0.5 만(0.35 는 잡음 반점을 글자로 만듦), '설명 못 한 잉크' 에서 20 px 미만 반점 제외, 옆 잉크 검사 문턱 0.5.
  잡음 반점이 큰 글자 사이를 이어 한 줄이 40 성분을 넘으면 그 줄의 큰 글자(셋째로 큰 높이의 30 % 이상)만 다시 묶는다(모든 읽기 공통).
- **틀 파일**: `ref/gen_ocr_templates.py` 가 기본 2 509 개(이전과 바이트까지 같음 — 고딕 6 글꼴을 먼저 처리하고 중복 빼기)와 추가 3 534 개를 따로 쓴다. `diff_ocr.js` 144 → 301 KB.
- **시험** (`test/ocr` 에 조건 `gms` 60 장 추가, 840 장): 명조 3 가지(Liberation Serif = Times 치수, 틀과 같은 가족·다른 크기 / Caladea·DejaVu Serif Condensed = 틀에 없음), 바탕 8–20·잡음 σ 3–6.

- **한계**: 대문자 10–19 px 의 GMS 꼴은 대부분 못 읽는다 — 가는 명조 획이 잡음에 묻힌다. 이때는 conf 가 낮아 사용자 확인을 묻는다(오답이 확신으로 나오지 않음). 아주 어두운 바탕(중앙값 < 8)에서 검은 몸통이 안 보이면 못 읽을 수 있다. 반대 극성 읽기는 막대 둘레만 중앙값을 거르므로 2048² 에서 0.3–0.6 s.
